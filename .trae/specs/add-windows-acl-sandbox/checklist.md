## 首次授权的等待反馈（已实现，机制已验证）

- [x] 授权超过 **1 秒**才提示；1ms 的幂等命中（常态）**不出声**，避免每条命令闪噪音
- [x] 只提示一次，不重复刷
- [x] 提示文案说清三件事：在做什么、为什么慢、会不会一直这样
      （只说「请稍候」会让用户以为卡死）
- [x] 授权失败时不留悬挂定时器（`vi.getTimerCount()` 直接断言）
- [x] 已授权过的目录第二条命令不再提示

**实现路径与原计划不同，记录在此**：原计划「新增 IPC 通道 + 渲染层改动」。
实际发现 pi 的 `execute` 第 4 参数就是进度回调（`onUpdate`，`task-tool.ts:204`
已在用同一形态），链路 `onUpdate` → `tool_execution_update` → `tool_progress`
→ 工具卡 `detail` → `chat-view.tsx:572` 已经全通。所以**零 IPC 改动、零渲染层改动**，
提示直接落在用户正在等的那张 powershell 卡上；终态 `tool_finished` 整卡替换
（`conversation.ts:426`），提示是瞬时的、不污染最终结果。
DESIGN.md 的约束因此不涉及（没有新的视觉元素）。
