# 团队协作（Agent Teams）根基盘点

> 2026-09-16。背景：WorkBuddy 专家团机制已完成逆向（`docs/workbuddy分析/12-expert-teams.md`），
> 决策更新：**Teams 要做**，此前 add-subagent-task-tool spec 里"明确不做 Teams/SendMessage"
> 是过时决策。本文是动工前的现状审计：逐条对照 WorkBuddy 团队机制所需能力，盘我们
> 的根基哪些已就绪、哪些是欠账、哪些会直接踩坑。证据来自四路并行代码审计（行号级）。

## 0. 总评

会话底座（多桶并发、per-session 互斥、进程内多 SessionHost、worktree、审批归属、
防线三件套）**质量不错，大部分能复用**。真正的从零项集中在三块：**会话间通信、
通用子会话投影、共享任务存储**。另有一个**今天就存在的 bug**（侧栏不过滤子代理
会话）和一个**将来必踩的坑**（LRU 逐出会误杀闲置成员会话）。

## 1. 逐项对照（WorkBuddy 机制 → 我们的现状）

## 2. 会直接踩坑的四个点（动工前必须知道）

### 2.1 专家→工具面联动：路径已勘明，3 文件 5 处

experts.ts 加可选 `extraTools?: string[]`（解析缺省不抛错）→ daemon 装配处
（index.ts:1484）把专家 extraTools 与 `mode.tools` 合并走**现有 toolsOverride 通道**
→ `setExpert`（session-host.ts:875）需重新应用工具集（宿主加一个注入的解析回调，
照 getExpertLabel L397 的现成模式）。字段可选、语义为白名单追加，无破坏性。
**这也是"团队工具四件套按专家开关"的同款落点**——WorkBuddy 的 expertType 模式
在我们这里就是把 `expertType:"team"` 换成 expert 声明 `extraTools:[team 工具]`。

### 2.2 成员 host 的生命周期：LRU 会误杀

`pickEvictions`（session-registry.ts:183-198）对空闲桶做 LRU 上限 5 逐出。
子代理是即弃会话（跑完 dispose）无所谓；**团队成员是长期挂靠的**——用户跟领导
聊半小时，闲置成员会被静默逐出，SendMessage 唤醒时"已不存在的成员"正是
WorkBuddy 文档自认的已知限制（无恢复）。我们的选择：①成员桶加"团队挂靠"豁免
逐出；②像 WorkBuddy 一样接受"成员收消息时重建"。必须显式决策，不能默认踩。

### 2.3 侧栏不过滤子代理会话（今天的 bug）

`listSessions`（daemon/index.ts:1791-1829）**不过滤** `subagent_run` 会话——
`markSubagentRun` 写的溯源条目目前唯一消费方是 usage-stats。团队动工后成员会话
数量暴涨，这个缺口会从"偶尔混进一条"变成"侧栏不可用"。应先修：列表按
`subagent_run`（将来加 `team_member`）过滤，或折叠进父会话的子分组。

### 2.4 投影通道是专用的，不是平台能力

subagent_progress 的生产方是 task 工具自己拼投影、session-host 只认
`details.subagents` 这一个键。ChildAgentProjection 式的通用"子会话事件面"
（双 kind、身份路由、busy/idle、rekey/retire 防幽灵）不存在。做团队时如果
继续在 task 工具里长，会把专用通道越撑越歪——**应该先抽一层通用的
child-agents 投影模块**（session-host 认事件不认工具），task 工具与未来的
team 工具都走它。

## 3. 建议的地基施工顺序

1. **修 2.3（列表过滤）+ 2.1（extraTools 联动）**——都小、独立、马上有用；
   后者是团队开关的前置。
2. **配置最小落点**：不求补完 config.get 全账，先按 memoryEnabled/thinkingLevel
   现成范式加 teams 开关 + 把预算/超时从常量参数化（读偏好）。
3. **通信原语**：daemon 内 Mailbox（按 sessionId 收件箱 + 定向投递 + 广播）+
   少量 IPC（member:send 之类，走既有 5 层加通道清单）。
4. **通用子会话投影层**：把 subagent_progress 抽成 child-agents 模块
   （双 kind、状态机、busy/idle、防幽灵三件套照 WorkBuddy 抄）。
5. **共享任务存储**：todo 从消息流投影升级为可落盘、带 owner/依赖的数据
   （新存储文件，别改坏现有 todo_write 契约）。
6. **成员生命周期**：桶豁免/重建策略二选一（§2.2 显式决策）+ worktree per-member。
7. **UI 层最后**：状态栏、@补全、焦点导航、任务面板、成员权限卡。
