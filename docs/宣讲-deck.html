怎么做到的

三条关键决策

一 · 不自研内核

pi 放在 WorkBuddy 放 OpenAI Agents SDK 的同一个位置。不 fork 上游，把类型挡在适配层里。

代价：上游破坏性变更必然发生。
收益：升级只塌一个模块。

二 · 对标是规格书，不是模仿

WorkBuddy 决定「做什么」—— 我们照它列了 212 条逐项可勾的对齐清单。

「怎么做更好」横向比 WorkBuddy / codex / deepseek-harness 三家择优，机制哪家强用哪家。

三 · 能力是数据，不是代码

模式、提示词、体裁、设计 token 全部放资源目录，代码只负责读。

判据：加一个体裁或模式，应该是加一个目录、零行代码改动。

这三条支撑了一个更重要的工程习惯：写下 38 条决策记录， 每一条都必须写明「否决方案」 —— 被否掉的路和否掉的理由。 它的作用是防止同一个决定被反复推翻。

数据安全与合规 · 1/4

三道防线，每一道都画出了它自己的盲区

把盲区画出来，是因为假装没有盲区比承认有盲区更危险。

01
权限门 —— 决定「要不要问人」
三档预设（只读 / 默认 / 完全访问）；目录外写入要确认；凭据目录（~/.ssh、配置目录）任何档位一律拒绝，连弹窗都不给。
盲区：它看得到 write / edit 的目标路径，但看不见一条 shell 命令内部要往哪儿写。
↓
02
危险命令检查器 —— 决定「这条命令能不能跑」
拦五类：动态执行 / 下载执行 / 凭据目录读取 / 递归强制删除 / 系统破坏。
盲区：它是静态文本匹配 —— base64 重编码、变量拼接、写成脚本再执行，三种都能绕过。
↓
03
操作系统级写沙箱 —— 决定「这个进程实际能碰到什么」
不再靠「猜这条命令想干什么」，而是由 Windows 内核回答「它能写哪儿」。约束从猜测变成事实。

一个具体到可以当场验证的例子

数据安全与合规 · 3/4

两条真实攻击面，是靠写探针脚本测出来的，不是靠直觉

这一类发现最能说明问题：直觉上「只读」的命令，行为其实由工作区里一个可被改写的文件决定。

一 · git status 可以执行任意命令

工作区里的 .git/config 写上 core.fsmonitor， 那么每次 git status / git diff 都会执行它指定的程序。

而「工作区内的写入免审批」是原本的设定 —— 于是模型可以静默埋一条持久化的执行链。

二 · 扩展文件加载即执行

.pi/extensions/*.ts 在会话建立时就被加载，并以本进程权限执行 —— 权限门在它之后根本拦不到。

项目信任机制自己也标注了：这是唯一一个跑在工具层之前的攻击面。

对策：「配置即代码」写保护

判据是 —— 内容会被自动执行，且没有任何命令点名它。

命中的一律高风险询问，即使它在工作区内。名单包含 .git/**、.pi/extensions/**、 package.json、.github/** 等。

为什么值得单独讲

如果没测这一步就上「免审批放行」，交付的就是一条零审批的任意代码执行路径。

探针脚本在仓库里可复跑，不是一次性的结论。

我们把「防不住什么」写进了产品界面

强制力恒为 partial

沙箱生效时，界面也不会把状态改成「完全受约束」。

一共 11 条已知边界，逐条写在文档里。

截图位：设置页权限区「未受操作系统级写入约束」的提示行

挑四条最要紧的，当场说清楚

  • 读不受约束。沙箱机制上只管写。所以「读走密钥」这条路至今只有命令检查器拦得住 —— 我们因此明确规定：不得因为「有沙箱了」就削弱检查器。
  • 网络不受约束。程序照样能联网外发。要做到禁网只能走专用账号那一档，代价见上一页。
  • 管理员用户基本不受约束。这是 Windows 安全模型的边界，不是我们的 bug，已实测确认。
  • 程序自建私有权限目录时可能写不进。我们给出了正规出路：一次性提权，且必须用户点头，绝不自动放宽。
假边界比没有边界更危险 —— 因为人会以为有保护。 所以我们宁可把「防不住什么」写在设置页上，也不让界面替我们吹牛。

单独做了一层「真实进程冒烟」

它跑在 Electron 的 utilityProcess 里，也就是 daemon 的真实形态，不是终端里跑测试。

原因很具体：终端进程有控制台，daemon 是无控制台的 GUI 进程，两者在受限令牌下行为可能不同。

这条纪律来自一次真实回归 —— 终端测试全绿，而应用里每一条命令都失败。

安装包本身也验过

已经在省：提示词前缀缓存

原理一句话：系统提示词位于整段对话历史之前，它里面一个字节的变化，会让其后全部历史在缓存里失配，代价随会话长度放大。

所以立了一条纪律：逐轮会变的事实（时间、工作目录、记忆内容、个性化）一律不许进系统提示词。

实测对照（同一会话内，看差值不看绝对值）

提示词字节不变 93.2% 命中
变更一行 62.0% 命中

会话级加权命中率从 90.9% 提升，目标 ≥95%。命中率不是仪表盘上的装饰，它可以直接换算成 token 钱。

现场演示 · 脚本

四段，每段一个价值点

段 做什么 想让你们看到 万一不顺
1 拖进一份真实业务文件 → 一句话 → 出一份 .docx，右侧面板预览、下载 闭环交付。不是聊完就结束，是直接拿到能交出去的文件 切录屏
2 默认档跑一条命令；再让它往工作区外写文件 → 被拒；打开设置页看沙箱诊断 敢让它动手，但它动不了不该动的地方 —— 这是刚才安全那几页的现场证明 切录屏 + 口头补
3 联网搜索出结论；切模型；同时开两三个任务并行推进 工程完整度。不是单点 demo，是能同时干几件事的工作台 跳过搜索那段
4 打开统计页 + 任务诊断面板，看刚才那几轮花了多少 token、命中多少缓存 成本可算账。花在哪儿、花了多少，当场就能看到 用截图
演示纪律：宁可少演一段，不演没验过的路径。 翻车一次，前面二十页的可信度都会打折。

诚实页

还没做的，和被明确接受的代价

未完成

  • 记忆：「以后周报都用这个格式」这类跨会话偏好，现在还记不住
  • 文档生成：docx 已可用；PDF 与完整报告流水线尚未开工
  • 团队协作：底座已盘完（并发会话、审批归属、预算与超时都在），主体功能未开工
  • 代码签名未做：首次启动会有 SmartScreen 蓝色提示，属预期，需要点「仍要运行」

被明确接受的代价

  • 离线 / 内网不可用：运行时按需下载、首次使用需联网。这是为了让安装包不含运行时载荷而接受的代价；接内网镜像需要另行拍板
  • 读与网络不受沙箱约束：写侧有内核级保证，读和联网没有
  • 不补跑错过的定时任务：应用关闭期间本该跑的任务不会补，属有意设计
  • 手动分发、不做自动更新：避免给同事带来未经同意的变更
把这一页放在演示之后、讨论之前：我们不需要靠信息不对称来争取信任。
嘉立创Work · 阶段汇报

讲什么

  • 主动讲，别等追问。尤其是签名和内网这两条，一旦被当作「你没告诉我」发现，损失远大于现在说。
  • 「被明确接受的代价」这个措辞很关键 —— 它们不是疏漏，是有理由的取舍，理由都写在决策记录里。
