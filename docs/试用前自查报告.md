## 二、问题清单（按优先级）

### P0 — 功能性缺陷 ✅ 已修复（2026-09-17）

**MCP 工具注册了，但模型永远调不到。**
- 链条：mcp-client 把工具注册成 `mcp__<server>__<tool>` → pi 的 `createAgentSession` 把 `tools` 数组当作**激活名单**（pi sdk.js:141 `options.tools → allowedToolNames`），且 `_refreshToolRegistry` 对扩展工具**先按名单过滤再放行进注册表**（agent-session.js:2117）→ 三个模式白名单（resources/modes/*.md）都不含 `mcp__*` → 工具连注册表都进不去，事后 `setActiveToolsByName` 无效。
- 症状：连接器页显示「已连接，N 个工具」，模型实际一个都调不到。
- 为什么测试没拦住：smoke:mcp 用假 ExtensionAPI 验证注册，从未端到端验证「模型侧可见」。
- **修复**（对齐 WorkBuddy 的「MCP 一等公民」口径——同名 `mcp__server__tool` 进名单与权限规则）：session-host 新增 `extraActiveTools` 选项，MCP 工具名在**构造时**并入 `tools`（扩展工厂在 `resourceLoader.reload()` 里同步跑完，名字此刻已就绪）；daemon 传 `mcpClient.registeredToolNames()`。MCP 工具调用仍由权限门逐次审批（permission-policy 的 MCP 分支，凭据拦截/只读拒/审批语义不变）。
- **验证**：新增 `smoke:mcp-activation`（真实 pi 会话 + 本地 stdio echo server，零网络可跑），断言激活集同时含模式白名单成员与 MCP 工具，3/3 通过。
- 已知边界：会话**中途**新配置的 server（名单快照之外）其工具要下个会话才可见；名单内 server 的启停/重连不受影响。

## 三、分发与环境准备（宣讲前必须落实）

**分发形态：NSIS 安装包**（2026-09-17 起支持）。打包链：`npm run dist:dir`（免安装目录，快速冒烟）与 `npm run dist`（安装包 `release/JLC-Work-Setup-<版>.exe`），配置见 electron-builder.yml。要点：

- productName 嘉立创Work，用户级一键安装（%LOCALAPPDATA%\Programs\嘉立创Work，免管理员），桌面 + 开始菜单快捷方式；卸载保留 ~/.kamibuddy。
- resources/ 随包物理化（extraResources），main 起 daemon 时注入 KAMIBUDDY_RESOURCES_DIR；uv.exe 随包（resources/bin/，npm run fetch:uv 拉取或手工放置），main 前置进 daemon PATH——同事机器**核心功能零预装**（无 Node/Python/管理员要求；Win10/11 x64）。
- 原生模块（koffi / clipboard / canvas / console-mode 的 .node）由 electron-builder smartUnpack 解包——打包后必须验 app.asar.unpacked 里有它们（koffi 动态 import 解包失败会报「不是有效的 Win32 应用」）。
- asar files 白名单只收 out/** + package.json（开源项目/docs/.trae 等绝不进包）——每次改 files 配置后必须 npx asar list 复查。

**同事机器上的已知依赖与说明**：

1. **MCP 连接器需 Node.js**：连接器 command 来自用户配置（如 npx），目标机器须自备 Node（或配置绝对路径命令）。
2. **docx 首次转换需联网**：uv 装 Python 3.12 + PyPI 依赖（约 1-3 分钟）；受限网络设用户级环境变量 UV_INDEX_URL（PyPI 镜像）与 UV_PYTHON_INSTALL_MIRROR（Python 发行版镜像），daemon 经 process.env 透传给 uv；或运维预置 venv / HTML_TO_DOCX_VENV 指向。
3. **SmartScreen/杀软**：安装包未签名，首次运行 Windows 会拦——「更多信息 → 仍要运行」；国产杀软对 NSIS 误报加白。签名是后续正式化事项。
4. **数据位置**：配置与会话 ~/.kamibuddy、文档产物 ~/KamiBuddy，卸载保留。
5. 模型凭据：统一用公司中转（jlc）的 baseUrl + Key + 「鉴权走 Authorization 头」勾选。
