# 可视化通用规则（所有类型必读）

## 分工：文字进响应，视觉进工具

- 解释、分析、结论、建议——全部写在普通的文字回复里，照常输出。
- 图表、流程图、结构图这类视觉内容——只通过 show_widget 提交，它会内联渲染成文字回复旁边的一张卡片。
- 两边都不要越界：不要在文字回复里粘贴大段 SVG/HTML 代码；也不要把整段报告文字塞进 widget 里，widget 只放"看"的部分。
- widget 是补充，不是替代品。没有 widget 的那段文字也必须能独立讲清结论。

## 片段规则（硬校验，违反会被直接拒收）

你提交的是**片段**，会被注入宿主页面的卡片容器里，不是一张完整网页：

1. 禁 `<!DOCTYPE>`、`<html>`、`<head>`、`<body>`——只写片段本体。
2. 禁 `localStorage`、`sessionStorage`——沙箱环境禁止访问，一碰就抛异常。
3. 禁 `position: fixed`——卡片高度靠文档流随内容自适应，固定定位会脱离文档流：既量不出正确高度，还会浮在聊天界面上到处遮挡。同理不要写死整个片段的像素高度（图表容器除外，见 chart 模块）。
4. 禁 `<form>`——片段没有提交目标。需要输入交互时，用普通控件（button / select / input）加事件监听自己处理，不要包 form。

## 外观基调：融进消息流

- 扁平、紧凑、克制，像聊天界面里长出来的一张信息卡，不是一张海报。
- 禁 emoji——用图形和文字表达。
- 禁渐变、阴影、模糊这类装饰效果：一方面与消息流气质不符，另一方面片段是流式逐步上屏的，装饰效果在生成过程中会闪烁抖动。

## CSS 变量（宿主按明/暗主题注入，直接用，不要自己另造）

| 变量 | 用途 |
| --- | --- |
| `--bg` | 卡片底色 |
| `--text` | 主文字 |
| `--text-secondary` | 次要文字、坐标轴标签 |
| `--text-dim` | 更弱的辅助文字、刻度、说明 |
| `--border` | 分隔线、描边 |
| `--radius-md` | 圆角（容器、卡片） |

HTML 片段开头建议带一小段基础样式（总共不超过 15 行，流式上屏才稳）：

```html
<style>
  .widget { box-sizing: border-box; margin: 0; padding: 0; color: var(--text); font-size: 13px; line-height: 1.5; }
</style>
```

主题适配：HTML/CSS 部分直接用上面的变量即可跟随明暗切换；需要按主题分叉时可用 `@media (prefers-color-scheme: dark)`（宿主保证 iframe 内该媒体查询可用）。

## 排版：字号三档、字重两档

- h1 15px / h2 14px / 正文 13px，不要引入第四档字号。
- 字重只用 400（正文）和 500（标题与强调），不用 600/700。

## 外部资源：CDN 白名单（CSP 强制）

片段的沙箱 CSP 是 `default-src 'none'`，只有以下四个域名放行，其余来源的脚本/样式/图片一律被浏览器拦截：

- `cdnjs.cloudflare.com`
- `cdn.jsdelivr.net`
- `unpkg.com`
- `esm.sh`

不要引用任何其他外部 URL；图标用 SVG 自己画，不要拉外部图片。

## 无障碍

- 可交互元素（按钮、开关、 tab 等）必须有可读的 `role` 与 `aria-label`。
- `<canvas>` 必须写 `role="img"` 和描述图表内容的 `aria-label`，标签内再放一段等价的 fallback 文本。
- 颜色不能是信息的唯一载体：上升/下降除了红绿，还要有 ↑↓、+/- 或文字标注其一。

## 选择实现路线

- 能纯 SVG 画清楚的（流程图、结构图、示意图），优先 SVG——免脚本、流式上屏最稳，见 svg-setup 与 diagram 模块。
- 数据统计图表（柱/线/饼/条）走 chart 模块的 HTML + Chart.js 路线。
