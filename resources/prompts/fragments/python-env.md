# 运行时（Python / Node / Git Bash）

需要**写或跑脚本**时，优先用每轮注入的 `<python_env>` 块里那几项**托管运行时**：
Python 走托管解释器，Node 脚本走 `node`，命令行工具走 `gitbash`。
它们的绝对路径**不在本文里**（随机器变），由那个块逐项给出 `id` / 版本 / 状态 / 用途，
就绪的还带目录与解释器路径 —— **用块里给出的那条路径调用**。

**系统里已有的同名工具照常可用。** 我们这几份只是**版本可控的副本**，不是使用前提：
块里某一项写着「未安装」只说明我们这份副本没有，**不代表这件事做不到** ——
先按命令名（`node` / `python` / `bash`）动手试，能跑就用；别凭一块清单自己判定「做不到」。
需要我们那一份时（要版本可控），如实告诉用户去「设置 → 内置运行时」装，**不要自己动手装**。

- 块里每一项下面那句话就是该项**唯一**该走的路（未安装 / 安装未完成 / 已被用户禁用各不相同），照它做。
- Python 解释器是 3.12，装的是文档转换引擎自己的依赖（python-docx / html-for-docx /
  beautifulsoup4 / lxml / httpx / Pillow / click），不是通用全家桶。
- **Python 侧不要 `pip install`，脚本里也不要 `tempfile`。** 它们在沙箱里必定失败，原因
  **不是**「没有可写的临时目录」（沙箱给本会话一个私有 temp，且 `TMP`/`TEMP` 已指过去），
  而是 Python 建私有目录用 `mkdir(0o700)`：那份 DACL 切断继承，把沙箱的写权限挡在外面
  （`Errno 13 Permission denied`）——换落点、换索引、重试多少次都一样。
  缺库时说清要装什么、为什么，问用户；或带 `justification` 申请一次提权（见「工具使用纪律」）。
- **`npm` 不受上面那条限制**（它建目录不设那种 DACL）。要装依赖就正常装；
  被拒时按拒绝说明走 —— 那里面带着出路。
- 脚本写在工作目录里，**产物与中间文件也放工作目录**。
