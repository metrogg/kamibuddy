# 内置运行时（Python / Node / Git Bash）

需要**写或跑脚本**时，用系统内置的托管运行时：Python 走**托管解释器**，Node 脚本走
清单里的 `node`，命令行工具走 `gitbash` —— 不要去猜系统里那份，也不要装包。
它们的绝对路径**不在本文里** —— 它们随机器变，由每轮注入的 `<python_env>` 块给出
（块里是**运行时清单**：逐项 `id` / 版本 / 状态 / 用途，就绪的还带目录与解释器路径）：

- **用清单里给出的那条路径调用**（如 `& '<清单里 python 那一项的 Python 解释器路径>' script.py`）。
  清单里没给路径的运行时（例如尚未就绪或没登记可执行文件的），不要自己猜 `node.exe` /
  `bash.exe` 在哪 —— 用 `node` / `nodejs` 这类命令名是否可用如实判断，拿不准就问用户。
- **先看状态那一列再决定怎么做**：
  - 「就绪」→ 直接用清单给的路径。
  - 「未就绪（尚未准备）」→ 首次使用会自动准备（需联网，约 1-3 分钟）。先等待，
    或如实告诉用户环境正在准备；**不要自己动手装**。
  - 「准备失败」→ 如实说出失败原因，并请用户在「设置 → 内置运行时」点「诊断」看报告、
    或点「重置并重新安装」。
  - 「已被用户禁用」→ 那是用户自己的选择：不要调用它、不要安装它，直接告诉用户
    「这个运行时已被你在设置里关掉」，并请他在「设置 → 内置运行时」重新打开。
- Python 解释器是 3.12，里面装的是文档转换引擎自己的依赖（python-docx / html-for-docx /
  beautifulsoup4 / lxml / httpx / Pillow / click），不是通用全家桶。
- **不要 `pip install`。** 沙箱里它必定失败 —— pip 会在临时目录里自建一个沙箱
  写不进的子目录，换落点、换索引、重试多少次都一样（`Errno 13 Permission denied`）。
  这里没有你要的库时，说清楚要装什么、为什么，问用户；或带 justification 申请一次提权。
  同理不要 `npm install`：清单里有什么就用什么，缺能力就问用户。
- 脚本写在工作目录里，用**清单里那个路径**调用。
  **产物与中间文件都放工作目录**，脚本里不要用 `tempfile` 或系统临时目录
  （理由同上：沙箱写不进那类目录）。
